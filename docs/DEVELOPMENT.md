# 开发说明

## 边界

- `game/` 是唯一 Godot 工程。外层管理文档、原画与工具，保留外层 Git。
- `main.gd` 只装配；`stage/` 管场景部件，`camera/` 管构图与过渡，`scripted/` 管固定剧本，`presentation/` 管演出采样，`ui/` 管显示和操作。
- 规则、AI、表现分离。表现状态不进入公共日志或任何 AI 上下文；未来 AI 输出必须校验，玩家引用统一 `{seat:0}` 占位符。
- 席位数按配置和公式计算；出局不重排席位。人物朝桌心，背面剪影，禁止 billboard／固定屏幕尺寸。
- 同一角色按高度与脚底基准保持尺度；宽度不限，不能为容纳宽姿态缩小人物。
- 白天围护墙与门板收进地面，棚顶收至高处；夜晚围护升起、棚顶下降形成隔离舱。白天应能从外圈看到立牌的黑色背面。
- 原画与参考目录不导入 Godot。正式运行资源放 `game/assets/`。界面、台词、桌面色钟罗马数字与讲台铭牌统一用思源宋体 `assets/fonts/SourceHanSerifCN-Regular.otf`，并在 `project.godot` 的 `gui/theme/custom_font` 里设为全局默认字体，新增控件不用再单独指定。

## 美术

每个运行时角色目录的 `chara.yaml` 保存名称、专属颜色、牌位 ID、可选的脸部位置和状态表：

```yaml
name: ChatGPT
color: "#8fa9ff"
memorial: 11
focus: 0.11
states:
  0: 常态.png
  2: 发言.png
```

`states` 是数字 ID 到同目录 PNG 的映射，0 必需；新增 ID 与图片不需要改代码。名称与颜色只用于显示层，颜色进入讲台/字幕/投票头像，不参与规则。项目不再维护角色 JSON 总表，直接扫描 `game/assets/characters/*/chara.yaml`，按每个文件的 `seat` 字段排序。剧本 `pose` 只接受非负整数，不兼容中文状态名或数字字符串；未配置的 ID 回退 0。`focus` 是脸部/眼睛从 PNG 画布顶部往下的位置比例，范围 0..1；标定时用眼睛所在的纵坐标除以整张 PNG 高度（包含透明留白），并放在 `states:` 之前。角色构图注视点取脸下方 0.25m，DR2 位置锚点再比注视点高 0.05m。未配置时按状态 0 的 alpha 顶部加 0.10 估算脸部位置。YAML 仅支持上述一层嵌套，不支持列表、锚点多行等完整语法。

**一键导入**：新图放进 `art/<角色>/` 后双击 `导入立绘.bat`（`tools/art/import_characters.py`）。它会扫描所有含顶层 PNG 的角色目录，复制新图和更新图；源目录中仍存在的旧图保留原状态 ID，新图按标准名补 ID（常态0/从容1/发言2/沉思3/观望4/质疑5/被质疑6/反驳7/愤怒8/失落9/无奈10/牌位11/头套12/得意13），未知文件名追加到最大 ID 之后。回写 `chara.yaml` 时保留已有 `focus`；不会删除运行目录里多出来的图，也不会自动生成缺失的标准状态。导入后重启演出即可。

立绘放在 `game/assets/characters/`，该目录带 `.gdignore`，Godot 不会导入，因此不会在旁边生成大量 `.png.import`。运行时用 `FileAccess` 读取字节、`Image.load_png_from_buffer()` 解码并缓存 `ImageTexture`。立牌开 4x MSAA + `alpha_to_coverage` + alpha scissor：边缘平滑且在移动镜头下不闪毛边；背面固定为纯黑剪影，不显示正面图案。**导出时必须把 `assets/characters/**` 和 `*.yaml` 加入非资源文件过滤**，否则导出包内没有立绘与配置。字体走常规导入，会保留一个 `.import`；新增字体文件后需先跑一次 `Godot --headless --path game --import`。

## 剧本

当前默认剧本是 `game/scripted/demos/first_trial_v3.json`（35 段，223 秒，标准 12 人狼人杀：4 狼/4 神/4 民，上警、对跳、警徽流、验人、归票、放逐、夜里刀/验、猎人枪）。台词按 `art/*/人设.txt` 与 `art/人设总纲.txt` 重写；`first_trial_v2.json` 与旧 `first_trial.json` 保留为对比/回归样本。命令行可切换：`Godot --path game -- --script=first_trial_v3`，截图用 `--at=秒数 --capture=路径`。

公共频道只写公开可见的发言与系统播报，不写心理、姿态或身份；狼队与预言家信息只出现在 `wolf` / `private` 频道。`speaker`、`camera_seat`、`memorial_seats` 等全部使用 0 基索引，正文占位符 `{seat:N}` 也使用 0 基索引。一段台词可以放一到三句，不必一人一句。

发言/侧拍可写 `dr2_shot`（如 `"PAN_L_00"`、`"FIXED_03"`）指定 DR2 原始机位；不写则继续用 `camera_preset` 的旧机位。表情全部走剧本数据，不改代码：`pose` 是发言者的起始表情；`pose_changes: [{at, pose}]` 让同一段发言按进度换立绘（`at` 为 0..1 的段内进度，取已到时间点的最后一项，seek 结果一致）；`reactions: [{seat, pose}]` 给旁听者指定公开反应表情，一段写三四个即可。所有 pose 必须是该角色 `chara.yaml` 里存在的 ID，缺失时按 0 回退。默认剧本已尽量让同一角色每次出场换不同表情，并轮换旁听者的反应。

## 镜头与时间

真实 Camera3D 产生透视和遮挡；旧伪 3D 工程仅提供概念，不移植其投影和参数。席位由连续台沿连成完整的圆，开场在圈外高位看整圈。

角色是固定在席位上的 3D 立牌，始终朝桌心，不随相机转动；只有出场/退场改变位置。讨论镜头以**恒定角速度**绕桌旋转，角度只由绝对时间决定，换人不会改变转速。机位半径、高度、视场在 `camera/shot_library.gd` 的预设里维护，剧本用 `camera_preset` 引用：

- `close`：圈内近景，胸口以上；用于质疑/被质疑。
- `medium`：圈内中景，能带到全身和相邻席位；发言默认。
- `outer`：圈外斜侧全景，不站到发言者正对面，避免最近立牌挡住画面。
- `high`：桌心正上方俯视，只用于封舱/开舱等阶段转换。

换角色时直接切镜，只有同一位角色连续发言才在 0.6 秒内平滑过渡；换机位也直接切，不斜穿桌面。剧本写 `"camera_transition": "cut"` 可强制切镜。普通机位用 `arena.base_seat_transform()` 保持构图稳定；竞选升降时由 `camera_rig.set_lifts()` 把目标高度和机位高度一起抬起，保证升起的角色不被切头。`camera_target` 可覆盖注视高度（空席看桌面用 `0.95`）。右上角常显分辨率、实际 FPS、帧率档位与当前机位；窗口与 1600×900 画布 1:1。默认帧率策略：60Hz 屏锁 60 并开垂直同步；≥100Hz 屏默认**不限帧率、关闭垂直同步**（HUD 显示“不限”）。原因不是缺补帧，而是软件限速和显示器扫描会缓慢错相：锁在刷新率附近时，偶尔会有一帧没赶上扫描，只能复用上一帧，转圈就会顿一下；渲染得比刷新率快，每次扫描都能拿到最新帧。实测比“跟随屏幕 ×2”更顺，代价是显卡接近满载。`F5` 循环“不限 / 跟随屏幕 ×2 / 60 / 120”，`--fps=120` 可强制帧率；不想听风扇时切到“跟随屏幕 ×2”或 60。

开场共 17 秒，分三段：0–3.27 秒复用旧 OUTER 机位在席位圈外平视转满一整圈（保持原 110°/秒，能看到完整一圈 12 人，近侧黑剪影保留）；3.27 秒硬切到内圈，半径 2.1m、高 2.4m、朝外看同侧席位、注视 2.2m、FOV 40，匀速转满一圈，经过人物时不停顿。15 秒起锁定 0 号席位，在 2 秒内继续以 0.125m/s 推近，不在结尾定格。路径全部是绝对时间的函数，可任意 seek。普通对话的中景/近景用更明显的慢速横向漂移，避免镜头看起来“定死”。`镜头预览.bat` 打开机位控制台：左侧面板用下拉框选择“DR2 原版镜头 / 旧机位预设”，DR2 支持家族筛选、镜头名搜索、座位、竞选升起、进度拖动（自动播放/重播）、距离倍率滑杆（默认 ×0.30）和锚点高度滑杆。锚点滑杆范围 0.4–3.2m，默认按角色 `focus` 自动计算，拖动只覆盖本次预览，切换角色恢复自动值，不会回写 YAML。旧机位预设直接选 close/medium/outer/high。

命令行可指定 `--dr2=PAN_L_00 --seat=1 --progress=0.5`，座位从 1 开始，指定进度后暂停播放。`--center` 改用房间中心锚点；`--anchor=` 设置中心锚点高度，`--focus=` 设置注视高度，两者单位都是米（`--focus` 不是 YAML 里的比例值）；角色模式的位置锚点自动取注视高度加 0.05m。`--fov=` 锁定正值视场角，`--scale=` 设置距离倍率，`--nopitch` 清零原数据俯仰偏移。旧机位可用 `--preset=high --legacy --no-ui`，`--capture=` 指定截图路径。`checks/preset_capture.gd` 仍可批量输出旧机位预设截图。

### 立绘巡览（录屏）

双击 `立绘巡览.bat`，或运行 `Godot --path game --script res://checks/portrait_gallery.gd`：默认 0–3.27 秒用旧 OUTER 机位在圈外转满 360°，全员常态；随后硬切内圈，半径 2.1m、高 2.4m、朝外看同侧席位、注视 2.2m、FOV 40，默认 10 秒一圈，连续匀速、经过人物不停顿。每席的展示顺序是**固定的**，写在 `checks/portrait_gallery.gd` 的 `FIXED_ORDERS` 里，按角色目录名索引：11 个普通状态按项目主指定的顺序逐圈切换，「牌位」固定为第 12 张。顺序只在启动时读取一次，seek 与切换都不重排；新增角色未配置时退化为 常态→从容→…→无奈→牌位。外圈和第一个内圈的前 12 拍都体现各席自己的随机序列；表情只在该席位整张立绘离开画面后才切换。默认关闭辉光、不显示任何 2D UI，方便录屏。bat 顶部变量可调 `LAP/OUTER_LAP/OUTER_HEIGHT/OUTER_RADIUS/RADIUS/HEIGHT/TARGET/FOV`；命令行对应 `--lap/--outer-lap/--outer-height/--outer-radius/--radius/--height/--target/--fov`，另有 `--at=秒` 和 `--capture=路径`。要直接出视频就双击 `立绘巡览-录制.bat`：Movie Maker 按固定步长逐帧渲染（外圈约 3.3 秒 + 12 圈 × 10 秒，60 FPS），再用 ffmpeg 转成 `captures/gallery.mp4`，中间 AVI 成功后删除（`KEEP_AVI=1` 保留）。第一个参数可覆盖时长，如 `立绘巡览-录制.bat 3` 只录 3 秒做测试。

### DR2 原始机位（默认接入口）

`参考/dr2/TrialCamStudy/cameras.json` 已拷到 `game/data/trial_cameras.json`（860 个镜头）。`camera/dr2_camera.gd` 只读采样，`camera_rig.gd` 在 `mode == "dr2"` 且剧本段写了 `dr2_shot` 时接管发言/侧拍；每个镜头是 2 关键帧线性插值，按段内已过秒数采样，seek 可复现。

实测出的数据约定（与原汇报不同，必须按这里来）：

- **位置单位**：原数据 1 = 0.1m；本项目立绘 2.8m，约为原版角色的 1.6 倍。取 `0.30` 做距离（比原版近景再退一档，避免脸贴镜头）；预览面板选的镜头仍按这个系数换算。
- **旋转单位**：原数据 1 = 0.1°。必须**先 look-at 注视点，再叠加数据旋转偏移**；采样器的 `pitch_scale` 默认 `0.35`，减弱原数据过大的俯仰偏移。传 `0` 可清零该偏移，预览用 `--nopitch`。
- **锚点**：角色镜头按各自 `chara.yaml` 的 `focus` 计算注视点，取脸下方 0.25m；位置锚点比注视点高 0.05m，随席位升降一起移动，不再统一套用 2.2m/2.15m。全景可用 `center` 房间中心锚点，高度由剧本或 `intro_cuts` 配置。
- **FOV**：数据没有独立 FOV 字段，但第二个旋转分量随 `ZOOMIN`（38→20）与 `ZOOMOUT`（20→38）反向变化，当前把它当 FOV，限制在 26–60°。采样器新增 `fov_lock`，正值时锁定视场角并覆盖数据值；普通 DR2 剧本段可用 `dr2_fov`，预览用 `--fov=`。
- 已绑定的家族：`FIXED / PAN_L / PAN_R / PAN_U / DOLLYIN / DOLLYBACK / DOLLYUP / ZOOMIN / Q_ZOOMIN / HANRON_START_L/R`，共 17 段发言/侧拍。
- **按原版时长播，不要拉伸**：原版 `Duration` 本身就有 1/3/4/6 秒几档，铺满整段会把快镜拖慢。现在按原版时长播放，播完后绕注视点做极慢漂移，避免长台词段完全定格。
- **穿模保护**：采样出的机位如果低于地面（`y < 0.35`）或飞出房间（水平半径 `> 15.2`），这一镜直接放弃、交回旧机位；`ENO_* / ROLL_*` 这类会钻地或大角度翻滚的镜头不要绑到普通台词上。
- **环绕镜头**：`shot: orbit` 或写了 `camera_orbit: true` 的宽景，按 beat id 生成 4 个确定性控制点并平滑插值，seek 可复现。整圈全景的控制点放在席位圈外侧，半径 8.6–9.8m、高度 4.4–5.2m，注视桌心；竞选段写 `orbit_seat`（0 基索引）后，改用圈内半径 3.6–4.8m、高度 2.6–3.4m，在目标席位正面附近小幅环绕，注视点随该席位升降。立牌只朝桌心，竞选人物镜头放到外圈会拍到黑色背面。
- **震屏**：原版数据只有 2 个关键帧，不含抖动；判定段用剧本字段 `camera_shake`（度）叠加确定性旋转抖动，只转镜头、不推位置，幅度在段首 0.6 秒内线性衰减到零，seek 可复现。
- `FIXED_*` 本来就是固定机位，不会动；预览面板会在信息里标明“移动 x.xxm / y.y°”或“固定机位（不会动）”，默认选 `PAN_L_00`。

旧的 `shot_solver` 全部保留：开场外圈/内圈、圈外全景、投票俯视、处决、退场/牌位这些没有 DR2 等价物的镜头仍走旧机位；`--camera=legacy` 可让整场回到旧机位对比（开场仍使用同一套外圈→内圈路径）。HUD 左上角标题下常显当前机位：`机位：DR2 原版 · PAN_L_00` 或 `机位：旧机位 · OUTER`。

投票改用俯视桌面＋小头像的专用视图（`ui/vote_board.gd`），不再让竖立立牌承受极端俯角；头像直接使用 `vote` 机位对真实席位坐标的投影，因此和桌边座位一一对齐，不再另画示意圆。票型按投票人各自的颜色画曲线箭头（末端带箭头），桌心显示按权重合并的得票合计。头像取每个角色原图的头部区域。所有演出由绝对虚拟时间采样，暂停与 seek 不依赖播放历史。

## 中央圆桌

桌面是 12 块 30° 扇形板拼成的实心圆盘：内半径 0（没有中心孔），拼缝宽度 0（没有物理空隙），顶面只留 2mm 深色缝线。桌心不放玻璃盘、显示环或第二圈装饰；从高位俯视看到的是完整的一块钟面。钟面不设指针：12 个罗马数字对应 12 个席位，0 号在 XII，用思源宋体平铺、统一朝上（不随半径旋转，避免底部数字倒置）；每两个数字之间 4 根小刻度用该席位在 `chara.yaml` 的颜色，整点大刻线为蓝色。

## 讲台与竞选

主光位于桌心正上方，影子自然落向每个角色身后；侧向光只作柔和补光，不投影。讲台为实心分层结构：底部三层基座台阶（踢脚、承台、金属上收口）、中间收腰的三段柜体、两侧贴合的装甲翼与金属压条、上方的斜托架，以及“承梁→台板→45mm 金属内嵌框”的台面，接缝处露 12–24mm 装配线，不留透空。每种材质合并成一个 MeshInstance（每座 8 个，12 席 96 个）。前侧圆盘里不再显示七段数码管编号，改为悬浮铭牌：思源宋体、纯白填充、用角色自己的颜色描边；颜色与座位全部读 `chara.yaml`。舱顶仍有一块朝上的数码管编号，高位俯视时能直接读座位号；数码管固定两位（01…12），文字里的位次则写成「6号」，不补零、不加“席位”。每个席位常亮自己的颜色：讲台灯带、舱内竖向灯条与低位补光，警长另有金色编号与警徽光；不做头顶光环，也不加会随升降穿过固定席位环的地面圆环。舞台材质不做自发光（`Geometry.make_emissive` 只保留反照率），亮度全部来自真实灯光；席位地面光池已移除，桌面与讲台顶面用哑光材质，色灯不产生高光反射。候选者上警时人物与整座席位一同升起，退水回落，当选后回落并保留警长标记。竞选高度与警长状态从剧本绝对时间重建，不靠一次性 Tween。

## 退场演出

投票出局：聚光、彩带、翻板开启、人物坠落；当天保留空席，次日切对应角色牌位。彩带共 30 片，用进度映射绝对时间并采样弹道：初速由 `sqrt(2 * GRAVITY * RISE)` 求得，当前重力为 9.80m/s²、上抛增高为 2.20m；每片按固定延迟发射，落地后用 0.35 秒缩小并隐藏，seek 可复现。不能再让彩带随进度一直上浮后停在半空，否则会留下悬空碎片。夜间死亡：不坠落，技能演出完成后，天亮以左右错位近景和远景揭示牌位。猎人开枪与人物退场分开编排；被毒不能开枪的规则由未来规则层校验，样片只演示预编排效果。

性能采样（开发用，加载主场景后逐帧记录间隔）：

```bash
./tools/godot/Godot_v4.7.2-stable_win64_console.exe --path game --script res://checks/benchmark.gd -- --at=160 --bench-frames=600 --bench-unlimited
```

实测 RX 580 / 1600×900 / 144Hz：默认“不限”时轻负载镜头约 2.5–3.5ms 一帧；“跟随屏幕 ×2”（288fps、关垂直同步）跑开场旋转、竞选升降、夜间换装、结尾环绕各 400 帧为 `avg≈3.47ms，p95≈5.05ms，p99≈5.45ms，最差≈6.56ms`，全部落在 144Hz 的一次刷新（6.94ms）以内。注意这些帧时间包含限速/呈现等待，不代表 GPU 成本；此前 120Hz 下测到的 8ms 大多被呈现/垂直同步挡住了。之前的三处卡顿来源分别是：锁在刷新率附近时软件限速与扫描错相、垂直同步把偶发慢帧放大成整帧；兼容渲染器的全七档辉光 p95 约 10.5ms；播放中第一次解码立绘 PNG 单次可达约 100ms。现在开场前用 `Catalog.preload_script_states()` 预解码全剧用到的表情、表情切换与旁听反应，辉光只保留中段三档，高刷屏按 2 倍刷新率渲染，立绘纹理开 8× 各向异性过滤以减少转圈时的边缘闪烁。
